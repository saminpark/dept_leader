# Fran:D 실장 업무실

대시보드에서 할 일을 점검하고, 14개 업무 영역의 체크리스트를 편집하며, 지정한 Google 문서에 날짜별 탭으로 기록하는 개인 업무 웹페이지입니다.

## 바로 사용

- **화면부터 보기:** 함께 제공된 `FranD_Director_Desk.html`을 브라우저로 엽니다. 파일 실행에서는 체크·편집·JSON 백업을 사용합니다.
- **Google 연결까지 사용:** GitHub Pages에 배포하거나 `start-local.bat`을 실행합니다. 첫 1회 Google OAuth 설정이 필요합니다. 자세한 순서는 **[SETUP_KO.md](SETUP_KO.md)**에 있습니다.
- Python이 설치된 환경에서는 `python serve.py`를 실행하고 `http://localhost:8000`을 엽니다.

## 들어 있는 기능

| 화면 | 기능 |
|---|---|
| 대시보드 | 전체 완료율, 진행·결정 대기·기한 경과·예정 업무, 집중 업무, 실장 메모, 14개 영역 진행 현황 |
| 영역별 체크리스트 | 상위 업무 62개와 하위 할 일 186개가 기본 포함됩니다. 새 업무를 추가하고 모든 제목·설명·결과물·담당·기한·상태·우선순위·메모·근거 링크를 편집합니다. |
| 전체 할 일 | 영역을 가로지르는 검색, 상태 필터, 기한·우선순위 정렬 |
| Google 저장 기록 | 본문까지 저장이 확인된 기록과 탭 링크, 중단된 저장 이어서 확인 |
| 연결 설정·백업 | Google OAuth, 대상 문서 지정, 새 문서 생성, JSON 백업·복원, 초기화 |

업무들은 이전에 정리한 실장 업무체계의 **편집용 제안 템플릿**입니다. 최초 상태는 모두 미착수이며 담당자·기한은 비워 두었습니다. 업무 완료 또는 공식 인사 배정을 뜻하지 않습니다. 초기 템플릿에 실제 재무 수치, 개인 연락처, 비공개 문서 원문은 포함하지 않았습니다.

### 편집 방식

업무의 `편집`에서 상위 제목·메모와 하위 목록을 바꿉니다. 상위 완료 체크는 하위 목록도 완료 처리합니다. 완료 업무의 하위 항목을 다시 열면 상위 상태도 진행 중으로 돌아옵니다. 보관된 업무는 기본 진행률 집계에서 제외하고 보관함 필터에서 복원할 수 있습니다.

점검 주기(매주·매월·분기)는 분류 정보입니다. 새 할 일을 자동 생성하거나 알림을 보내지는 않습니다. 반복 업무의 다음 실행은 복제 후 기한을 설정하세요.

## Google 저장의 정확한 동작

한 문서 안에 **실제 Google Docs 문서 탭**을 생성합니다. 별도 파일 14개나 스프레드시트 시트를 만드는 기능이 아닙니다.

```text
[사업 전략·우선순위] 2026-10-08
[조직설계·채용·평가·육성] 2026-10-08
[사업 전략·우선순위] 2026-10-08 (2)
```

영역별 저장은 새 탭 1개, 대시보드의 전체 저장은 새 탭 14개를 순서대로 생성합니다. 제목 날짜는 한국시간이며 사용자가 변경할 수 있습니다. 완료 업무와 진행 메모를 포함할지 미리보기에서 고릅니다. 기존 탭을 덮어쓰거나 삭제하지 않습니다.

Google 저장본은 **그 시점의 읽고 편집할 수 있는 스냅샷**입니다. Google 문서에서 바꾼 내용은 웹페이지에 역동기화되지 않습니다. Docs에 보이는 `☐`·`☑`는 상태 텍스트이며 Docs 고유 체크박스 위젯은 아닙니다. 웹페이지의 체크리스트가 실행 상태의 기준입니다.

성공 응답만 보고 완료 처리하지 않고 저장된 본문의 식별 문구를 재조회해 확인합니다. 응답이 끊기면 `Google 저장 기록 → 이전 저장 이어서 확인`을 사용합니다. 본문은 이미 저장됐다면 이력만 복구하고, 확인된 빈 탭에는 당시 스냅샷을 이어서 기록합니다.

## 세 가지 저장 위치

| 위치 | 보관 내용 |
|---|---|
| GitHub | 웹페이지 코드와 초기 체크리스트 템플릿 |
| 현재 브라우저 | 실제 업무·체크 상태·담당·메모, 대상 문서 설정, 저장 이력 |
| 지정 Google 문서 | `구글로 저장하기`로 전송한 업무 스냅샷 |

브라우저 데이터는 자동으로 GitHub에 커밋되지 않습니다. 다른 PC·브라우저·사이트 주소로 이동할 때 **JSON 백업 → 새 환경에서 불러오기**로 작업을 이어갑니다. 로컬 캐시를 지우거나 시크릿 모드를 종료하면 브라우저 기록을 잃을 수 있습니다.

## GitHub Pages

저장소에 파일들을 올리고 **Settings → Pages → Deploy from a branch → main → /docs**를 선택합니다. `docs/`에는 배포할 정적 파일만 들어 있습니다. Pages 운영 여부·공개 범위는 GitHub 플랜과 조직 정책을 확인하세요. 일반 Pages 배포는 공개 사이트이므로 실제 인사·고객 메모가 들어 있는 JSON이나 비밀키는 커밋하지 않습니다.

## 개발 구조

```text
index.html, styles.css       화면 구조·스타일
seed.js                     14개 영역의 초기 제안 템플릿
core.js                     상태 검증·진행률·Google 보고서 구성
google-docs.js               문서 탭 생성·본문 작성·결과 검증·중단 복구
app.js                      화면·편집·로컬 저장·OAuth·Picker
config.js                   비어 있는 연결 기본값 (설정 화면에서 입력 권장)
docs/                       GitHub Pages 배포 사본
build.py                    docs/와 단일 HTML 재생성
serve.py, start-local.bat    로컬 실행
SETUP_KO.md                 배포·Google 최초 연결 가이드
SECURITY.md                 데이터·권한·보안 범위
TESTING.md                  검증 범위와 실제 Google 연결 확인 절차
tests/                      Node 단위/API 모의 테스트와 UI 테스트
```

설정 화면에서 입력한 값은 현재 브라우저에만 저장됩니다. Client Secret·서비스 계정 키·액세스 토큰을 입력하는 칸은 없습니다. OAuth 클라이언트 ID는 공개 식별자이며, Google Picker용 브라우저 API 키에는 웹사이트와 API 제한을 적용합니다. 액세스 토큰은 메모리에만 보관합니다.

## 재생성·테스트

```bash
python build.py
node --test tests/core.test.cjs
python tests/ui_test.py
```

일반 사용에는 Node와 Playwright가 필요 없습니다. UI 테스트만 Python Playwright 및 Chromium이 필요합니다. 검증 환경·미검증 항목은 `TESTING.md`를 확인하세요. 업무 데이터와 템플릿의 업데이트는 별개입니다. 배포 파일을 교체해도 이미 편집 중인 브라우저 기록을 초기 템플릿으로 덮어쓰지 않습니다.
